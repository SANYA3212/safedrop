# Проверка кода SafeDrop — 2 ноября 2026 (версия 0.3.28 → 0.3.29)

## Как проверяли

Код разделили на пять частей, каждую читал отдельный агент. Каждую находку я перепроверил по коду, прежде чем исправлять.

| Часть | Файлы |
|---|---|
| Ядро | `src-tauri/src/main.rs` |
| Сеть и файлы | `signal.rs`, `state.rs`, `transfer.rs`, `quic.rs` |
| Браузер и «Смотреть вместе» | `ytbrowse.rs`, `yt-browser.html`, `yt-chat.html`, нужные части `app.js` |
| Интерфейс, 1-я половина | `src/app.js`, строки 1–3000 (чат, звонки, микрофон, звуки) |
| Интерфейс, 2-я половина | `src/app.js`, строки 3000–6032 (настройки, темы, «Смотреть вместе», браузер) |

Мелкие файлы отдал OpenCode: `discovery.rs`, `settings.rs`, `tls.rs`, `src-shell`, `tauri-shim.js`, сборочный скрипт, права окон. За 40 минут он не выдал ответа, видимо, ждал разрешения. Эти файлы я просмотрел сам: опасных `unwrap` на внешних данных нет, права у окон правильные.

Что проверено после правок:
- `cargo check` проходит без ошибок и предупреждений.
- Все 12 тестов проходят (два новых: проверка картинок и ограничение длины сетевой строки).
- Синтаксис `app.js`, `tauri-shim.js`, `yt-browser.html` и `yt-chat.html` проверен через `node --check`.
- Интерфейс открыт в демо-режиме: ошибок в консоли нет. Поиск в настройках больше не сбрасывает поля (проверено на «Имя ПК» и галочке UDP).

Что не проверено:
- Вдвоём на двух ПК: звонки, передача файлов, группы и браузер.
- В настоящем приложении после сборки: проверена только сборка и установщик.

## Исправлено

### Серьёзное
| Где | Что было | Сценарий |
|---|---|---|
| `app.js` `avaInner`, `buildRow`; `signal.rs` `trim_avatar`, приём чата | Аватарка или картинка из чата вставлялась в страницу без проверки | Любой ПК в сети присылает «аватарку» со скриптом. Он выполняется в SafeDrop и может отправить ему любой файл с диска |
| `ytbrowse.rs` `on_navigation` | Любые схемы ссылок отдавались Windows (ShellExecute) | Сайт или присланная другом страница открывает `file://…\x.exe` или `search-ms:`, и программа запускается без вопроса |
| `main.rs` `save_settings` | Страница присылала старую копию профиля и папки приёма | Сменил ник, потом поменял тему: ник откатился, и друзьям ушёл старый |
| `app.js` поиск в настройках | При сбросе поиска поля пересоздавались из старого HTML | После поиска имя ПК пустое, порты по умолчанию. «Сохранить» записывает мусор |
| `app.js` `hideCallUI`, `endGroupCall` | Микрофон не освобождался | Значок микрофона Windows горит до выхода из программы |
| `signal.rs`, `quic.rs` | Лимит кадра 1 МБ при 10 картинках по 700 КБ | Сообщение с 4+ фото не доходит и пересылается каждые 30 с |
| `signal.rs` `send_chat_sync` | Каждые ~30 с пересылалась вся история старше 500 сообщений, плюс квадратичная сборка пачек | Трафик и нагрузка на процессор в длинных чатах |
| `signal.rs`, `transfer.rs`, `quic.rs` | Чтение строки без ограничения размера и без таймаута | Вредный или зависший собеседник занимает всю память или вешает соединение навсегда |

### Среднее
- **Смена микрофона во время звонка:** раньше трек добавлялся без пересогласования, и собеседник слышал тишину. Теперь используется `replaceTrack`. Два запуска микрофона подряд больше не теряют один захват.
- **Ответ без микрофона:** у звонящего больше не идут вечные гудки, ему уходит отбой.
- **Превью камеры:** запоздавший поток останавливается сам.
- **Группы:**
  - «Удалить участника» записывается как уход, поэтому он не возвращается.
  - «Выйти» работает со всеми своими адресами.
  - Свои сообщения больше не отправляются самому себе.
  - Повтор сообщения не вызывает уведомление ещё раз.
  - Старое приглашение не воскрешает группу, из которой вы вышли.
- **Контакт с двумя адресами (LAN + Radmin):** проверка «жив ли» опрашивает все его адреса.
- **`add_peer`:** повторное добавление не стирает контакт.
- **Сохранение на диск** (`persist_*`): раньше молча пропускалось, если блокировка была занята. Теперь ждёт до 0,5 с.
- **Приём файлов:**
  - папка приёма больше не бывает пустой, раньше файл попадал в папку программы;
  - временный файл назван по номеру передачи;
  - конечное имя проверяется перед переименованием;
  - 60 с без данных считаются обрывом;
  - отменённая докачка не начинается заново;
  - вторая попытка докачать тот же файл вытесняет первую, а не дописывает его вдвоём;
  - не пишется больше заявленного размера;
  - обновление больше 512 МБ отклоняется.
- **Браузер:**
  - Только участники звонка могут вести «Смотреть вместе» и «Листать вместе».
  - События `emit_to` больше не доходят до чужих окон, поэтому чат и уведомления не дублируются.
  - Реклама YouTube не рассылается как перемотка.
  - Прокрутка, полученная от друга, не отсылается обратно.
  - «Закрыть у всех» действует только на тех, кто листает вместе.
  - Двойное открытие окна не выдаёт ошибку.
  - Время ввода со страницы ограничено текущим временем.
- **«Смотреть вместе»:**
  - Плейлист помнит номер играющего видео.
  - «Повторить» действительно перезагружает API YouTube.
  - id видео от собеседника проверяется.
  - Видео, начатое через «+ В очередь», не играет дважды.

### Мелкое
- Звуки: `blip` закрывает свой AudioContext, индикатор микрофона использует один контекст, свой длинный звук не обрывается через 6 с, мелодия не включается снова после ответа.
- Проверка гудков не трогает настоящий звонок.
- Неотправленное сообщение остаётся в поле ввода вместе с картинками.
- Пресеты тем копируются, а не правятся напрямую.
- В импортированной теме не принимается сетевой путь к фону.
- «Сбросить всё» удаляет `group-sync.json` и ключ CLSID меню Проводника.
- Плагин single-instance регистрируется первым.
- Пустая папка приёма в старом файле настроек заменяется на папку по умолчанию.
- Счётчик чата сбрасывается при конце звонка.
- Узкое окно браузера: у кнопок остаются только значки.

## Не исправлено (нужно решение или отдельная работа)

| Что | Почему отложено |
|---|---|
| Правки и реакции чата проверяются только по нику. Удаление группы и уход принимаются от любого ПК | Нужна проверка отправителя в протоколе: что разрешено и кому. Нужно продумать, чтобы не сломать группы у старых версий |
| Правка своего сообщения после смены ника не применяется у собеседника | Связано с пунктом выше: сопоставлять надо по адресу, а не по нику |
| Каждый `hello` (раз в ~30 с) заново шлёт все свои правки и реакции отдельными соединениями | Нужен список «ещё не подтверждено», это изменение протокола |
| Докачка от того же собеседника принимается без вопроса, даже если имя или размер файла другие | Нужно хранить имя и размер рядом с частью файла |
| `chats.json` целиком перезаписывается при каждом сообщении | Работает, но медленно на большой истории. Нужна отложенная запись в фоне |
| «Очистить кэш» удаляет часть файла, который сейчас скачивается, и не видит папку `.safedrop-partial` | Нужен учёт активных передач |
| Значения по умолчанию в старых `settings.json` (автозапуск, звук, «доверенный» контакт) не совпадают с настройками нового пользователя | Новые файлы пишутся полностью, так что это касается только очень старых установок. Менять опасно |
| Импортированная тема может подгружать CSS из интернета (`@import`) | Тему импортирует сам пользователь. Можно добавить вопрос перед импортом |
| Глобальный поиск по чатам: старые результаты могут перебить новые, сортировка по «ЧЧ:ММ» | Мелочь, работает |
| Ошибки части вызовов `save_settings` не показываются | Мелочь |
| Если у собеседника 0.3.28 или старше, сообщение больше 1 МБ до него всё равно не дойдёт | У старых версий свой лимит. Обновитесь оба |
