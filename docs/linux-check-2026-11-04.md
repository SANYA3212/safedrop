# Проверка Linux-версии — 4 ноября

Повод: на Arch камера и микрофон не включались («Микрофон: Invalid constraint»), а звонок показывал окно «Микрофон заблокирован» с SVG-кодом вместо кнопки.

## Исправлено

| Что было | Причина | Что сделано |
|---|---|---|
| Камера и микрофон: «Invalid constraint» | WebKit отвечает `OverconstrainedError`, когда ни одно устройство не подходит под обязательные условия: точный `deviceId` (в WebKit идентификаторы меняются между запусками, сохранённый устаревает) или пределы `max` камеры | `gumFallback`: точное устройство → то же устройство «по возможности» → любое с мягкими параметрами → просто любое. Запрет (`NotAllowedError`) не обходится |
| В списке устройств «Микрофон 1» без названий, выбор не запоминался | WebKit спрашивает разрешение `DeviceInfoPermissionRequest`; wry его не решает, и WebKit отказывает | Окно SafeDrop разрешает этот запрос (только главное окно) |
| Звонок при любой ошибке микрофона писал «Микрофон заблокирован» | `startCall` ловил все ошибки одинаково | `micFailed`: окно — только при настоящем запрете, иначе сообщение с причиной |
| На Linux в этом окне советы про «Настройки Windows» и кнопка «Сбросить запрет» (она там не работает) | Общий текст для всех систем | Свои подсказки для Linux, без кнопки сброса |
| Кнопка окна подсказки показывала SVG-разметку текстом | Подпись ставилась через `textContent` — **и в Windows** | Подпись (наша, из кода) ставится как разметка |
| Демонстрация экрана на Linux спрашивала про звук WebView2 | Вопрос рассчитан на WebView2 | На Linux показ сразу без звука: WebKit системный звук не захватывает |

Раньше в этой же ветке: WebRTC включается в WebKit сам, звонки идут через `max-bundle` (иначе соединение с WebKit обрывалось), камера и показ экрана разрешены окну SafeDrop.

## Как проверял

- Сборка под Linux и Windows — без ошибок и предупреждений; синтаксис `app.js` — OK.
- Пакет `safedrop` собран на Arch из исходников, установлен, запускается, порты 47831/47832 открыты; AppImage тоже запускается, внутри WebKit с WebRTC.
- WebRTC между двумя соединениями внутри WebKit: соединение и канал данных работают.

## Не проверено

- **Сама камера и микрофон.** В WSL нет устройств, а тестовые устройства WebKit там зависают — исправление сделано по коду WebKit (`UserMediaRequest::deny`, `InvalidConstraint`), проверить нужно на настоящем Arch.
- Звонок Linux ↔ Windows и демонстрация экрана (на Linux нужны `xdg-desktop-portal` и PipeWire).
- Встроенный браузер и «Смотреть вместе» на Linux.

Если камера или микрофон всё ещё не работают — запустить `safedrop` из терминала и прислать вывод, и текст сообщения об ошибке.
