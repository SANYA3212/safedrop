# Изменения

Все заметные изменения SafeDrop. Новые записи — сверху. Каждый коммит дописывает сюда, что добавлено и что починено (раздел «Не выпущено»), а при выпуске раздел получает номер версии.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Не выпущено]

## [0.3.34] — 2026-11-05

Основная версия (Latest) для Windows и Linux. Микрофон через PipeWire проверен на живом PipeWire в WSL, с настоящим микрофоном — ещё нет.

### Добавлено
- Linux: SafeDrop определяет, кто управляет звуком — PipeWire или PulseAudio, — и видит ли его GStreamer. В «Звонки и звук» → «Звук» показана звуковая система. Если звуком управляет PipeWire, а плагина GStreamer для него нет (Arch: `gst-plugin-pipewire`, Ubuntu: `gstreamer1.0-pipewire`), там же есть команда установки и кнопка «Установить»: пароль спросит сама система. В пакетах Arch плагин добавлен в необязательные зависимости.

### Исправлено
- Linux: микрофон не работал с PipeWire. В списке не было ни одного микрофона, а звонок и «Запросить доступ» давали «Микрофон: Invalid constraint» или «Микрофон заблокирован». Причина — нет плагина GStreamer для PipeWire: через него WebKit ищет микрофоны. Теперь вместо непонятной ошибки SafeDrop объясняет, в чём дело, и предлагает поставить плагин. Если микрофона действительно нет, пишет «Микрофон не найден».
- Одинаковые всплывающие сообщения больше не складываются стопкой: повтор продлевает уже показанное. Раньше каждая попытка звонка без микрофона добавляла ещё одну ошибку, и они заполняли пол-экрана.
- Linux: выпадающие списки в настройках были белыми, и текст на них не читался. Теперь они в цветах темы SafeDrop.

## [0.3.33] — 2026-11-05

Основная версия (Latest) для Windows и Linux. Отправка картинок между двумя ПК ещё не проверялась.

### Добавлено
- Сборка 0.3.33 для Linux: пакет Arch из исходников (`packaging/arch/safedrop` теперь собирает тег `v0.3.33`) и AppImage, в который встроен WebKit с WebRTC. Пакет `webkit2gtk-4.1-webrtc` остался тем же, 2.54.2-1.

### Исправлено
- Скриншоты и другие картинки в чате не доходили до собеседника, хотя текст доходил. С 0.3.31 соединения шифруются с ключами обеих сторон, и после рукопожатия собеседник присылал служебные данные (TLS session tickets), которые отправитель не читал. Закрытие соединения с непрочитанными данными Windows делает обрывом, и всё, что ещё не успело уйти, терялось: короткий текст успевал, а картинка в сотни КБ по Radmin — нет. Теперь отправитель ждёт, пока собеседник дочитает, а сам SafeDrop эти служебные данные больше не присылает, так что картинки от друзей на 0.3.31–0.3.32 тоже доходят. То же касалось хвоста файлов, отправленных без подтверждения (например, обновления).

## [0.3.32] — 2026-11-04

Не проверено между двумя ПК. Первая версия со встроенной в установщик подписью.

### Добавлено
- Три вида аудиоплеера на выбор в настройках чата: «Волна» (по умолчанию), «Компактный» и «Системный». Голосовые, аудиофайлы и предпрослушивание перед отправкой оформлены в цветах темы; кнопка «Отменить» тоже. Короткие голосовые получают волну по мере просмотра, одновременно играет только одна запись, а новые сообщения и реакции не сбрасывают прослушивание.
- Подпись обновления теперь внутри установщика: делиться и выкладывать нужно один `.exe`, без файла `.sig` рядом. Установщики 0.3.31 с отдельным `.sig` по-прежнему принимаются. Другу на 0.3.31 SafeDrop отправляет установщик в прежнем виде, с подписью отдельно, так что обновление примут и они.

### Исправлено
- При звонке появлялось «RNNoise не загрузился — включён встроенный шумодав WebRTC»: файл шумодава `rnnoise.mjs` не попадал в репозиторий (его скрывало правило для проверочных копий `*.mjs`), и в сборке 0.3.31 его не было. Теперь он на месте, RNNoise снова работает.
- Обновление от друга запускало установщик с ключами, которых NSIS не знает (`/SILENT /DIR=`), поэтому вместо тихой установки открывался обычный мастер. Теперь установка идёт с полосой прогресса и без лишних вопросов, ярлыки не трогаются, а SafeDrop перезапускается сам.

## [0.3.31-untested] — 2026-11-04

Не проверено между двумя ПК (pre-release). Сделано вместе с Codex: функции — Codex, ключи и подпись обновлений — Claude, ревью — друг за другом.

### Добавлено
- Голосовые сообщения с записью, предпрослушиванием, отменой и ограничением в две минуты.
- Пересылка текста и вложений контакту или группе с подписью автора.
- Отметки «Прочитано» в личных чатах и настройка отправки квитанций.
- Настройка STUN-сервера для звонков; по умолчанию выключена.
- Проверки Rust и синтаксиса JavaScript в GitHub Actions для Windows и Ubuntu.
- История звонков в «Звонки и звук»: входящие, исходящие, пропущенные и без ответа, 1:1 и групповые, с длительностью разговора (без гудков). Хранится только у вас, до 300 записей; «Сбросить всё» её удаляет.
- Закреплённые сообщения: «Закрепить» в меню сообщения, до 5 на чат, полоска над чатом с переходом к сообщению. Видны только у вас.
- Push-to-talk: в «Звонки и звук» можно включить разговор по удержанию клавиши (по умолчанию пробел). Микрофон заглушён, пока клавиша не нажата и когда окно теряет фокус.
- `AGENTS.md` — правила проекта для ИИ-помощников (Codex и др.): CHANGELOG, версии, UTF-8, проверки, что нельзя ослаблять в безопасности.

### Безопасность
- **Ключи устройств.** У каждого ПК свой постоянный ключ (тот же сертификат, что и раньше); теперь обе стороны соединения его предъявляют, и подпись рукопожатия проверяется. Раньше сертификат принимался любой и без проверки подписи — шифрование защищало только от подслушивания, а не от подмены собеседника.
- Ключ контакта запоминается при первом защищённом соединении. Дальше с этим контактом — только шифрование и только с тем же ключом: молчаливого отката на открытый текст больше нет ни при исходящих, ни при входящих соединениях (раньше хватало назваться старой версией или сорвать рукопожатие). То же для QUIC.
- Если контакт пришёл с другим ключом, соединения отклоняются и SafeDrop спрашивает, доверять ли новому ключу (нормально после переустановки друга, подозрительно без неё). В вопросе виден код нового ключа, и принимается именно он: если за это время пришёл ещё один, SafeDrop спросит заново. Новый ключ заменяет старый только у этого контакта.
- В карточке контакта — код безопасности из 12 цифр: у вас и у друга он одинаковый, сверьте голосом.
- Контакты на 0.3.26–0.3.30, которые ещё не умеют предъявлять свой ключ, продолжают работать по шифрованному соединению, пока ни разу его не показали; открытый текст от контакта с запомненным ключом не принимается никогда.
- **Обновления только с подписью.** Раньше любой контакт мог прислать любой `.exe` «обновлением», и после «Да» он молча ставился. Теперь `build-release.bat` подписывает установщик ключом SafeDrop, подпись едет вместе с файлом, и без верной подписи окна обновления нет — обойти кнопкой нельзя. Версия берётся из подписи, а не из того, что написал отправитель; откат на старую версию не ставится. Подпись проверяется ещё раз прямо перед запуском установщика.
- Предлагать друзьям «своё обновление» SafeDrop теперь может только подписанным установщиком.
- Править сообщение в группе может только тот, кто его прислал: автор определяется по адресу, с которого пришло сообщение (у контакта с запомненным ключом он подтверждён ключом), а не по нику — одинаковые ники больше не позволяют править чужое. Для старых сообщений и восстановленных из истории остаётся проверка по нику.

### Исправлено
- Голосовые сообщения и пересланное аудио доходят до получателя: сам файл теперь отправляется вместе с сообщением (раньше уходило только имя файла), под уникальным именем (раньше при совпадении имён у получателя играл его старый файл) и досылается вместе с сообщением, когда собеседник появляется в сети. Если файл всё же не дошёл, вместо пустого плеера написано «аудиофайл не получен». При досылке файл не уходит дважды, а без файла сообщение не досылается; копии для отправки, которые никому не ушли, удаляются.
- Голосовое уходит тому, кому его начали отправлять, даже если во время передачи переключиться на другой чат; ответ (цитата) и картинки при этом не теряются, а набранный за это время текст не стирается.
- Голосовое нельзя отправить дважды двойным нажатием, а запись нельзя запустить дважды двойным кликом (раньше второй микрофон оставался включённым). Закрытие окна останавливает запись (она остаётся неотправленной), выход из программы её отменяет.
- «Прочитано» отмечает все дошедшие сообщения до прочитанного, а не только последнее (недоставленные прочитанными не становятся); подсказка у галочек обновляется сразу.
- Включение push-to-talk снимает обычный мут — иначе говорить было нельзя совсем.
- Групповой звонок без ответа записывается в историю как «без ответа», а длительность считается с момента, когда кто-то подключился.
- Длинное название группы из сети больше не может уронить SafeDrop при записи в историю звонков.
- Закреплённые сообщения показывают текст после правки и исчезают, если сообщение удалено.
- Число одновременных входящих соединений ограничено (128 для сообщений и звонков, 32 для файлов): зависшие или зацикленные клиенты больше не могут занять всю память. Лишние соединения закрываются сразу.

## [0.3.30-linux] — 2026-11-04

Сборка 0.3.30 для Linux (ветка `linux`), для Windows ничего не меняется.

Пакет `safedrop 0.3.30-2` (4 ноября) — та же версия с исправлениями камеры и микрофона; отчёт: `docs/linux-check-2026-11-04.md`.

### Добавлено
- Сборка под Linux (ветка `linux`): `build-linux.sh` собирает `.deb` и AppImage, а `packaging/arch/PKGBUILD` делает из `.deb` пакет для Arch (`makepkg -si`).
- Автозапуск на Linux через `~/.config/autostart/safedrop.desktop`, отправка папок через `zip`, мигание окна через оконный менеджер.
- Звонки на Linux: SafeDrop включает WebRTC в WebKitGTK и сам разрешает своему окну камеру и показ экрана. Системный WebKit в Arch и Ubuntu собран без WebRTC, поэтому добавлен `packaging/arch/webkit2gtk-4.1-webrtc/PKGBUILD` — тот же WebKit 2.54.2 с WebRTC (около часа сборки, без LTO и отладочных символов: с ними линковка не влезает в 16 ГБ).
- `packaging/arch/safedrop/PKGBUILD` собирает SafeDrop для Arch прямо из исходников с GitHub (`makepkg -si`).
- Без WebRTC кнопки звонка, демонстрации и камеры говорят, чего не хватает, а входящий звонок сразу отклоняется, чтобы у звонящего не висели гудки.

### Исправлено
- Код только для Windows (меню Проводника, ярлык для уведомлений, мигание на панели задач) больше не мешает сборке на других системах. Под Linux в настройках скрыты кнопки Firewall, меню Проводника и страниц «Параметров Windows». Обновление через SafeDrop и сброс запрета микрофона на Linux честно говорят, что их нет.
- Звонки и демонстрации используют `bundlePolicy: "max-bundle"` (всё одним транспортом). WebRTC в WebKitGTK не поддерживает политику по умолчанию (`balanced`), и соединение с ним обрывалось.
- Описание программы в `Cargo.toml` было в сломанной кодировке и попадало в меню приложений Linux; у ярлыка появилась категория «Сеть».
- В подсказке «Групп нет» широкий «＋» заменён обычным «+»: без шрифтов CJK на Linux он показывался квадратиком.
- **Камера и микрофон на Linux падали с «Invalid constraint».** Сохранённое устройство (в WebKit его идентификатор меняется между запусками) и жёсткие пределы камеры WebKit не находил и отказывал. Теперь при неудаче SafeDrop пробует то же устройство мягко, потом любое.
- WebKit отдавал список устройств без названий и с пустыми идентификаторами («Микрофон 1»), выбранный микрофон не запоминался — окну SafeDrop теперь разрешено видеть устройства.
- Звонок с ошибкой микрофона всегда показывал «Микрофон заблокирован», даже когда микрофон просто не нашёлся. Теперь окно только при настоящем запрете, иначе — сообщение с причиной. На Linux в окне свои подсказки и нет кнопки «Сбросить запрет».
- Кнопка в окне подсказки показывала SVG-разметку текстом вместо иконки (и в Windows).
- Демонстрация экрана на Linux больше не спрашивает про звук WebView2: WebKit не захватывает системный звук, показ сразу идёт без него.

## [0.3.30] — 2026-11-03

### Безопасность
- Правки и реакции принимаются только от участников этого чата. Ник берётся из профиля собеседника, а не из самого сообщения. Удаление группы, выход из неё, приглашения и переименование — только от участников группы.
- Докачка файла без вопроса — только того же файла (имя и размер), который вы уже приняли.
- Синхронизация истории проверяет картинки и аудио так же строго, как обычные сообщения.
- Тема с внешними ссылками (`@import`, `url(http…)`) перед импортом спрашивает подтверждение. Отказ вырезает только эти куски.

### Исправлено
- Правка своего сообщения после смены ника теперь доходит до собеседника.
- Hello больше не шлёт все правки и реакции каждые 30 секунд. Догоняются только свежие, по одному разу и по очереди.
- История чатов пишется на диск в фоне одним сохранением, через временный файл. Сбой посреди записи больше не стирает историю, а команды чата не ждут диск.
- «Очистить кэш» не трогает скачиваемый сейчас файл, чистит части для докачки и правильные папки WebView2.
- Отправитель шлёт ровно заявленный размер файла.
- Глобальный поиск: сортировка по дате, без лишних загрузок, новые результаты не перебиваются старыми.
- Ошибки сохранения настроек показываются. Карточка справа сбрасывается после удаления группы.
- Микрофон после «Тест микрофона» вне звонка отпускается через 15 секунд.
- Значения по умолчанию для старых файлов настроек совпадают с настройками нового пользователя.

## [0.3.29] — 2026-11-02

Ночная проверка всего кода: исправлено больше 40 ошибок. Новых функций нет.

### Безопасность
- **Чужой ПК в сети больше не может выполнить код в SafeDrop через аватарку или картинку в чате.** Раньше в «аватарку» можно было спрятать команду, и она срабатывала, как только аватарка показывалась (контакт, входящий звонок, чат). Теперь принимаются только настоящие картинки — и при приёме, и при показе.
- **Сайт во встроенном браузере больше не может запустить программу на компьютере.** Ссылки с «необычными» адресами (`file:`, `search-ms:`, `ms-…:`) раньше молча открывались системой. Теперь системе отдаются только `mailto:` и `tel:`.
- «Смотреть вместе» и «Листать вместе» слушаются только участников текущего звонка: посторонний в сети не может остановить видео, увести браузер на свою страницу или закрыть его.
- Сетевые сообщения и заголовки файлов теперь ограничены по размеру и времени: зависший или вредный собеседник не может занять всю память или навсегда повесить соединение.

### Звонки
- **Микрофон выключается после звонка.** Раньше после первого звонка (или кнопки «Тест микрофона») микрофон оставался захваченным до выхода из программы.
- **Смена микрофона во время звонка** больше не делает вас немым для собеседника.
- Если при ответе на звонок микрофон недоступен, звонящий перестаёт слышать гудки и получает отбой, а вы — подсказку.
- Камера в настройках больше не остаётся включённой после закрытия панели.
- Гудки и мелодии больше не копят звуковые объекты (раньше за минуту звонка их набиралось десятки); мелодия звонка не возвращается после того, как звонок уже принят; длинные свои звуки уведомлений не обрываются на 6-й секунде.
- Проверка гудков в настройках больше не обрывает звонок настоящего собеседника.

### Чаты и группы
- **Сообщения с несколькими фото доставляются.** Раньше сообщение больше 1 МБ (примерно от 4 фото) молча не доходило и пересылалось каждые 30 с.
- **История чата больше не пересылается целиком каждые 30 секунд** в длинных чатах (больше 500 сообщений).
- Своё сообщение в группе больше не приходит самому себе с уведомлением Windows.
- Удалённый из группы участник больше не возвращается при следующем сообщении; «Выйти из группы» работает и на ПК с несколькими сетями (Hyper-V, WSL, Radmin).
- Вышедшая группа больше не воскресает из старой записи о приглашении.
- Не отправленное сообщение остаётся в поле ввода (с картинками), а не пропадает.

### Настройки и контакты
- **Смена ника, аватарки или папки приёма больше не откатывается**, когда потом меняешь любую другую настройку.
- **Поиск в настройках больше не ломает поля:** после очистки поиска имя ПК, порты и галочки сбрасывались, а следующее «Сохранить» записывало пустые значения.
- Повторное добавление уже существующего контакта больше не стирает его ник, аватарку и адреса.
- Изменения настроек, контактов и удалённые сообщения больше не теряются при сохранении на диск, если в этот момент работала фоновая проверка сети.
- Контакт, доступный только через второй адрес (например, Radmin), больше не «выпадает» из сети каждые 5 секунд и не обрывает звонок.
- Пресеты тем больше не портятся правкой CSS; в импортированной теме игнорируется фон по сетевому пути.
- «Сбросить всё» теперь забывает и группы, и пункт меню Проводника полностью.

### Передача файлов
- Файл больше не может оказаться в папке программы вместо папки приёма.
- Два файла с одинаковым именем (`photo.jpg` и `photo.png`) больше не портят друг друга при одновременном приёме, и один не перезаписывает другой.
- При обрыве без ошибки передача больше не висит «в процессе» вечно (60 с без данных — обрыв, докачка продолжит).
- Отменённая получателем докачка больше не начинается заново сама.
- Две попытки докачать один файл больше не дописывают его дважды.
- Получатель не записывает больше заявленного размера.

### Браузер и «Смотреть вместе»
- Сообщения чата в панели браузера больше не показываются дважды; уведомления не дублируются.
- Реклама на YouTube у одного больше не перематывает видео у всех.
- Одновременная прокрутка у двух людей больше не «дёргает» страницу туда-обратно.
- «Закрыть у всех» не закрывает браузер у тех, кто не листает вместе.
- «+ В очередь» при пустой очереди больше не играет видео дважды (в плеере и в браузере).
- Плейлист с одинаковыми видео больше не крутится по кругу без режима повтора; после удаления играющего видео следующим идёт то, что было за ним.
- «Повторить» в плеере теперь действительно перезагружает YouTube после сбоя сети.
- В узком окне браузера кнопки больше не уезжают за край.
- Двойной клик по «Браузер» больше не выдаёт ошибку.

Отчёт о проверке: [docs/audit-2026-11-02.md](docs/audit-2026-11-02.md).
